记录统计与 hint 各司其职

recorder 只供给数据；debug_hints 独立维护反压持续时间和信用账本，关闭或失信都不改变数据计量。

Hint 是辅助 debug 的观测线索。可信账本可以证明信用不足，但不能仅据此证明有待发送数据；hint 不充当传输许可，也不直接给出性能 PASS／FAIL。长时间阈值与输出规则单独配置。

最近的操作

    同一个 T，也有明确的逻辑顺序。

    每个统计范围由唯一入口串行提交。以下展示契约顺序，不表示已验证具体 SV 调度写法。

    timer / 完整帧 → 同一入口
    优先分支：本范围自身复位时，先中断本范围过程并清理其统计。成员复位不触发组自身复位。
    旧过程末次传输沿100 ns
    尾周期实际结束沿102 ns
    配置连续静默 Q30 ns
    确认旧过程／新传输132 ns

    132 ns 先确认旧过程结束，其计量终点是 102 ns；132 ns 的新传输属于新过程，也不计入在 132 ns 发布的窗口。

    停钟 · ns 模式

    timer 继续推进、历史继续过期，不等待不存在的采样帧。若尾周期尚未结束，就保留“尾界未定”，不估算周期长度。

    停钟 · cycle 模式

    周期索引、快照边界和结果保持。重复读取旧结果不增加新的阶段证据。

    复位清理自己的状态，历史不跨范围清空。

    身份、消费进度、窗口完整性与诊断可信性分别表达。

    POINT RESET

    成员 p0 自身复位

    清单点状态，继续向组交代它正在复位。

    • ↺p0 的窗口清空，过程复位中断，阶段证据重新积累；bw_debug_hints 的连续区间断开、信用账本重新初始化。
    • ＝POINT_ID 和注册关系不变，记录与采样序号不回退。
    • ＝A、B 的复位前事件继续按原窗口过期，不重新预热、不直接中断组过程。
    • →复位期间仍有复位记录。无采样沿时，复位断言／释放走单独的带时间戳控制通知。
    • →释放后的确定传输立即进入组，不等待 p0 再次满窗。
    GROUP RESET

    聚合组 A 自身复位

    只重启 A 的统计，不替其他订阅者决定记录寿命。

    • ↺A 的窗口清空，过程报告复位中断，阶段状态重置。
    • ＝p0、p1 与组 B 的统计保持独立，共享 package 不整体清空。
    • →A 在复位期间仍消费／确认经过的记录，避免拖住其他组。
    • ＝B 没确认的 p0 记录仍须保留；A 不能单方面删除。
    • →容量或统计数值表示越界明确终止；信用协议异常按诊断契约失信，不混为同一种错误。

    这些状态不能压成一个全局 valid

    窗口覆盖与字节完整性

    满窗不代表字节完整；污染离开窗口后，窗口完整性可以恢复。

    过程边界与过程字节完整性

    首末边界、尾周期与字节分别判断；过程曾含未知字节，不因窗口过期恢复为完整。

    阶段证据与过程是否完整

    短过程可以没有足够阶段证据，但仍有完整 e2e。零字节传输也能形成过程。

    Debug hint 的能力与当前可信性

    接口不支持某诊断，与支持但当前未知不同；信用失信不丢弃已确定的字节。
