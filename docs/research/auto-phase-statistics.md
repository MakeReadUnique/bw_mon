# 自动流量阶段识别与短滑窗统计研究

研究日期：2026-10-23。

对应决策票：**查证自动流量阶段识别与短滑窗统计的适用方法**。规范记录位于主工作目录的 `.scratch/bw-mon-architecture/issues/05-auto-phase-research.md`；本文在独立 `research/auto-phase-statistics` 分支保存，不作为已选定的架构，也不合并到实现分支。

本次查阅统计方法的一手文献及官方资料，没有实现 monitor、运行原型或验证仿真性能。下文明确区分“文献事实”“直接推导”和“设计候选”。

## 1. 已知需求与研究结论

用户已确定：纯仿真 SystemVerilog module；不依赖 testbench 阶段标记；窗口可选择 ns 或本地 clk，可能仅 10 ns；e2e 指一个完整流量过程的累计字节数除以持续时间，包含稳定段；允许可配置静默时长确认结束，后续流量另起一个过程；只观察 valid、valid-ready 或 flitv/lcrdv 接口，不增加 pending 等提示。

**结论是可以构造自动识别器，但必须把它定义为“在配置尺度与规则下的阶段估计”，不能承诺从任意有限流量轨迹恢复唯一的真实阶段。** 统计方法提供均值、波动、趋势或变点证据；“稳定”“爬坡结束”等业务语义仍需架构决策规定。未得到足够证据也是合法结果。

以下五个方面会直接影响架构：

1. 显示滑窗宽度、阶段分析尺度、最少持续证据和静默结束时长是不同参数；让它们可分别表达是值得讨论的候选。
2. 原始字节累计、滑窗曲线与阶段估计应保留各自的用途；e2e 不应靠把重叠滑窗样本再次累计来求字节数。
3. 识别“已经发生变化”的确认时刻，与对“变化何时开始”的估计边界，应能分别表示。
4. 零流量、没有样本、统计区间不足、未形成稳定段和仿真截断，需要独立的有效性描述。
5. 自动识别规则与性能 PASS/FAIL 门槛应分开；没有达到目标带宽并不意味着没有形成一个稳定的平台。

上述为根据需求及以下证据提出的架构候选，并非已选定方案。

## 2. 少量可比较的方法

| 候选方法 | 文献支持的能力与前提 | 在本项目中的候选用法与限制 |
|---|---|---|
| 有限区间线性拟合，结合均值与波动 | 最小二乘拟合通过最小化平方残差估计模型参数，直线模型可给出斜率。[NIST 线性最小二乘](https://www.itl.nist.gov/div898/handbook/pmd/section1/pmd141.htm) | 在有限历史内估计速率趋势，以正/负斜率支持爬坡/下降候选；小斜率加波动约束支持平台候选。不需要预知目标带宽，但分析区间、容差和持续证据必须配置。低斜率不等于低波动；周期突发也可能拟合成近零斜率。 |
| EWMA 平滑，结合趋势与持续判定 | `z[k] = λ·x[k] + (1−λ)·z[k−1]`；λ 决定新旧样本权重。标准 EWMA 控制界限需要历史基线，相关表格假设独立数据及正态总体。[NIST EWMA](https://www.itl.nist.gov/div898/handbook/pmc/section3/pmc324.htm) | 可用少量递推状态减小短期波动；快慢两种平滑的差异也可作为趋势特征。这种组合是工程候选，不是文献已证明的 SoC 阶段分类器。平滑有记忆效应；不能把控制图参数直接复制成未知流量的可靠置信度。 |
| 双向 CUSUM | 累积相对参考均值的偏差，可以检测均值向上或向下的变化；方法需要已知或估计的受控均值及尺度。[NIST CUSUM](https://www.itl.nist.gov/div898/handbook/pmc/section3/pmc323.htm) | 适合作为“已建立平台后是否离开平台”的候选检测器。若起始没有可靠平台，必须先建立参考或另设启动方法。不能只靠 CUSUM 同时完成未知平台发现、爬坡计时和静默结束。 |
| ADWIN 式自适应变点窗口 | 作者方法通过比较子窗口均值决定保留多少历史；理论设置要求样本独立、值有已知界，均值可未知。[Bifet 与 Gavaldà 原始预印本，第 3 节](https://www.cs.upc.edu/~gavalda/papers/adwin06.pdf) | 可作为无需预先固定分析历史长度的对照方案；它不取代用户要求的固定宽度显示滑窗。直接输入高度重叠的滑窗速率不满足原文独立性前提，因此不能沿用其误报界。实现及校准复杂度也高于简单递推候选。 |

这些方法都不能自行赋予“上升到哪个平台才算完成爬坡”的产品语义。选择简单拟合、EWMA 还是变点方法，仍要依据允许的识别延迟、噪声容忍、多平台段行为和大规模 bind 实例的成本决定。

如果将拟合斜率用于决策，时间坐标应使用实际经过的时间或明确的本地 cycle 序号。若采样间隔变化，直接按样本序号拟合得到的是“每样本变化”，不再等于“每 ns 变化”；这是模型单位的直接结果。

## 3. 小滑窗的三个直接推导

### 3.1 字节计数的量化

设每个成功传输事件计入 `q` 字节，统计窗口为 `W` 秒。窗口中增加或减少一个事件，会使报告带宽改变 `q/W` 字节每秒。例：64 字节事件、10 ns 窗口，对应一步 **6.4 GB/s**（十进制）。这是计量定义的直接推导，不是随机噪声模型，也不是对总线容量的假设。

因此小窗口下曲线呈阶梯并不自动表示 DUT 不稳定。即使输出保存很多小数位，也不会增加实际传输事件提供的信息。阶段识别应有最少观察时间或传输证据，具体门槛留给后续决策；不能设定一个对所有时钟和位宽通用的最少样本常数。

### 3.2 重叠滑窗的相关性

令底层等间隔样本 `x[k]` 独立、同方差 `σ²`，长度为 `m` 的平均值为 `y[k] = Σ x[k−j] / m`。相邻 `y` 共享 `m−1` 个底层样本，因此：

```text
Var(y[k])              = σ² / m
Cov(y[k], y[k−1])       = (m−1)·σ² / m²
Corr(y[k], y[k−1])      = (m−1) / m
```

这是在所述简化模型下的直接推导；真实 SoC 流量本身还可能相关。NIST 关于相关数据的研究也明确指出，过程数据独立性假设经常不成立，需要处理自相关对过程监测的影响。[NIST：Statistical Process Monitoring for Autocorrelated Data](https://www.nist.gov/publications/statistical-process-monitoring-autocorrelated-data)

设计含义：连续多个滑窗满足条件，可以作为配置的持续性规则；不能未经论证把它们当作同样数量的独立证据。用不重叠基础区间做分析能去掉“窗口共享样本”这一项原因，但仍不能保证底层流量独立。

### 3.3 平滑可以产生表观爬坡

考虑一个理想连续速率模型：真实速率在 `t=0` 从 0 瞬间变成常量 `R`。长度 `W` 的尾随平均值在 `0<t<W` 时为 `R·t/W`，到 `t=W` 才达到 `R`。其表观 10%→90% 上升时间为 `0.8W`，尽管这个理想输入没有渐变上升过程。这是对矩形窗口积分的直接推导，不是对离散 flit 的仿真结果。

设计含义：需要明确“爬坡时间”测的是所选平滑曲线的变化，还是根据原始活动估计的阶段跨度。后者也不可能无条件精确恢复，必须表达分析分辨率和检测延迟；更换显示窗口不应悄悄改变指标定义。

## 4. 波动与“稳定”的定义限制

NIST 将变异系数定义为标准差除以均值，并指出均值接近零时该量对均值的小变化敏感；它也不能直接用于求均值的置信区间。[NIST Coefficient of Variation](https://www.itl.nist.gov/div898/software/dataplot/refman2/auxillar/coefvari.htm)

因此可比较的设计包括：绝对标准差或范围；在均值和证据足够时才使用的相对波动；以及绝对项与相对项共同构成的容差。使用哪一种及其阈值尚未确定。把分母硬钳成任意小常数虽然能避免除零，却改变了指标含义，必须公开约定，不能当成统计正确性的证明。

对于不同持续时间的基础区间，过程平均带宽按定义应是 `Σbytes / Σduration`，不一定等于各区间速率的算术平均。总体波动采用等样本权重还是按时间加权，也需要明确。在线或合并式统计矩存在成熟数值方法，但这不免除本项目选择权重和区间的责任。[Sandia：带任意权重的稳定增量统计矩方法](https://www.sandia.gov/research/publications/details/formulas-for-robust-parallel-computation-of-arbitrary-order-arbitrary-varia-2015-02-01/)

“斜率接近零”“波动小”“均值达到期望值”是三个不同条件。阶段检测可以识别低于目标的稳定平台，性能检查再判定 FAIL。不能用“已达目标”来筛选稳定段，否则低性能平台可能从统计报告中消失。这是从需求推导的检查设计约束。

## 5. 阶段估计、确认时刻与边界

以下为候选契约，需要后续与用户决策，而非本文决定：

- 保留当前阶段候选、是否已确认、候选开始时刻、确认时刻、估计边界、证据量及统计有效性。
- 进入稳定和离开稳定可使用不同条件，配合持续时间避免边界反复切换；这些属于工程迟滞规则，不自动带来特定误报概率。
- 不能强制所有过程都出现完整的“爬坡→稳定→下降”：短突发、直接跳变、重复上升及多平台段可能没有足够证据完成每个阶段。
- 用显式有效性或原因表示“未找到稳定段”“采样不足”“过程被复位/仿真结束截断”，而不是伪造零时长、零波动或 PASS。
- 若输出的是评分，需区分工程证据评分与经分布假设校准的统计置信概率；不得把任意归一化指标命名为概率置信度。

仅靠已观察到的有限前缀，某一静默可能是暂时停顿，也可能是最终结束：两种未来可以共享完全相同的当前接口轨迹。这是可观察信息的直接限制。用户已接受的静默时长分段，正是将无法立即确定的未来转化为明确的操作性定义。

## 6. 全程平均带宽与静默结束

静默结束至少涉及两个不同时间：最后一次观察到的活动，以及满足静默确认条件的时刻。假设最后活动时刻为 `t_last`，静默阈值为 `T_quiet`，确认通常不能早于 `t_last + T_quiet`；实际确认粒度还取决于调度和采样策略。

**这不自动决定 e2e 分母是否包含静默等待。** 必须在后续决策中选择结束边界及首末事件的时间归属，并同时报告确认时刻，避免把检测延迟混入实际过程持续时间。若以最后活动作为回溯边界，应保留边界所需的计数快照或有界历史，不能拿确认时刻的平滑值倒推出累计字节。

还需规定：

1. 仅有一个传输事件时，`t_last−t_first` 为零；要么采用明确的采样区间归属，要么给出持续时间不足状态，不能除零。
2. 静默不足阈值又恢复传输时，这段间隙按当前分段策略仍属于同一过程；是否形成内部下降/再爬坡取决于阶段规则。
3. 静默超过阈值后重新出现流量时，按用户要求开启新过程，并保留前一过程的结果。
4. 仿真结束时仍有流量、或尚未满足静默确认，应标为未完整确认/截断；是否允许以观察截止点给出临时均值，由检查规则决定。

e2e 的字节数可直接来自所选观测点或聚合组的原始累计计数之差。单点或组的过程边界也应单独确定，不能默认所有 master 同时开始或结束。以上是计数与边界定义的推导，不依赖选择哪一种阶段识别算法。

## 7. 仅靠接口信号的诊断能力

本研究不把“没有观察到传输”解释为“上游一定无数据”，也不把它自动解释为“下游一定阻塞”。如果两个内部状态产生完全相同的外部信号轨迹，仅观察这些信号的 monitor 就无法区分它们。自动阶段分析不改变这一限制。

架构上可让诊断保留原始接口状态及能力说明，并让统计层保留字节与时间证据。针对 valid-ready 或 credit 接口，哪些信号组合足以证明某种等待、credit 是否可从复位点重建，属于另一个接口契约决策；本文没有假定 flitv/lcrdv 等价于 valid-ready。

## 8. 留给架构决策的选择

- 显示滑窗与阶段分析尺度是否独立，分析输入选原始基础区间还是显示曲线。
- 稳定段是低趋势、低波动的平台，还是允许周期性突发但长期均值稳定；多平台段如何报告。
- 使用哪组候选统计量，以及最少观察时长、可辨变化幅度、迟滞和确认规则。
- 爬坡/下降指标的参考边界、平滑依赖、回溯范围与有效状态。
- 静默确认等待是否进入 e2e 分母，以及单事件、截断和复位过程的处理。
- 基线学习和规则判定如何分离，哪些缺失证据影响 PASS/FAIL。

这些问题已有足够证据进入设计讨论，但本研究不指定算法、默认阈值或模块端口。
